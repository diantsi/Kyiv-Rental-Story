# Київська оренда: технічний стек MVP

## Мета

За один тиждень створити повністю прохідну вебновелу «Київська оренда: Рієлтори» для комп’ютерів і смартфонів.

Сценарій реалізується повністю: 13 сцен, усі репліки й вибори, три приховані параметри та п’ять кінцівок. Скорочення стосуються лише другорядних технічних функцій і складності мультимедіа, а не змісту історії.

## Обраний стек

### Інтерфейс і збірка

- **React** — компоненти інтерфейсу новели.
- **TypeScript** — типи сценарію, стану, виборів, прапорців і кінцівок.
- **Vite** — локальна розробка та production-збірка.
- **HTML і CSS** — діалогове вікно, кнопки, чати, оголошення, договір і фінальна статистика.

### Сценарій

- Сценарій зберігається як типізована структура даних у TypeScript або JSON-подібному TypeScript-модулі.
- Кожна сцена містить репліки, фон, персонажів, варіанти вибору, зміни параметрів, прапорці та наступний вузол.
- Для MVP **Ink не використовується**, оскільки поточний сценарій має спільну послідовність сцен і не потребує окремої сценарної мови.

### Стан гри

- **React `useReducer`** — єдине джерело стану гри.
- За потреби стан передається компонентам через React Context.
- Значення `relationships`, `budget` і `stress` завжди обмежуються діапазоном `0–100`.
- Reducer відповідає за перехід між репліками, застосування вибору, встановлення прапорців, визначення фіналу та перезапуск гри.
- Для MVP **Zustand не використовується**.

Мінімальна структура стану:

```ts
type GameState = {
  sceneId: string;
  lineIndex: number;
  relationships: number;
  budget: number;
  stress: number;
  flags: Record<string, boolean>;
  choices: string[];
  cheapChoiceCount: number;
  finalAction?:
    | "signed_after_edits"
    | "signed_without_edits"
    | "declined";
  saveVersion: number;
};
```

### Збереження

- **`localStorage`** — автоматичне збереження після кожного вибору.
- У головному меню доступні «Продовжити» та «Почати спочатку».
- Збереження містить номер версії, щоб майбутні зміни формату не ламали гру.
- Прогрес зберігається лише в поточному браузері та не синхронізується між пристроями.

### Аудіо

- **Howler.js** — фонова музика та звукові ефекти.
- Для MVP достатньо 1–2 музичних тем і 4–6 ключових ефектів.
- Звук запускається лише після першої взаємодії користувача відповідно до обмежень браузерів.
- Обов’язковий перемикач звуку.
- Прямий **Web Audio API не використовується**.

### Анімації

- **CSS transitions і CSS keyframes** — поява персонажів, зміна емоцій, повідомлення, підсвічення виборів і дощовий оверлей.
- Усі анімації короткі та не затримують читання.
- Ураховується системне налаштування `prefers-reduced-motion`.
- Бібліотека Motion для MVP не використовується.

### Тестування і перевірка

- Повне автоматизоване тестування не є вимогою MVP.
- **Playwright не використовується** у першій версії.
- Основні маршрути перевіряються вручну на комп’ютері та смартфоні.
- Якщо вистачить часу, **Vitest** використовується лише для 5–8 коротких тестів чистої логіки:
  - значення параметрів не виходять за межі `0–100`;
  - кожна з п’яти кінцівок досяжна;
  - пріоритет кінцівок працює правильно;
  - вибори встановлюють потрібні прапорці;
  - збереження коректно відновлюється.

### PWA

- PWA додається після завершення основного проходження гри.
- Мінімальна реалізація: manifest, іконки, service worker і кешування статичних файлів.
- Новела має відкриватися офлайн після першого успішного завантаження.
- PWA не повинна блокувати випуск браузерної версії, якщо наприкінці тижня бракуватиме часу.

### Хостинг

- **Vercel Hobby** — безкоштовний хостинг production-версії.
- Код зберігається у GitHub-репозиторії, підключеному до Vercel.
- Кожен push у головну гілку автоматично створює новий deployment.
- Налаштування збірки:

```text
Build Command: npm run build
Output Directory: dist
Install Command: npm install
```

- Vercel надає HTTPS, необхідний для встановлення PWA.
- Сервер, база даних і платні хмарні сервіси для MVP не потрібні.

## Функції, що входять у MVP

- усі 13 сцен без скорочення сценарію;
- усі сюжетні репліки й 39 основних виборів;
- параметри «Стосунки», «Бюджет» і «Стрес»;
- сюжетні прапорці та п’ять кінцівок;
- повідомлення про наслідок вибору;
- автоматичне збереження і продовження гри;
- початок нового проходження;
- діалоговий інтерфейс, чат, оголошення, чекліст і договір;
- фінальний екран із точними показниками;
- звук увімкнено/вимкнено;
- адаптивна версія для смартфона;
- базове керування клавіатурою і видимий focus;
- production-збірка та публікація на Vercel.

## Не входить у першу версію

- Ink;
- Zustand;
- Motion;
- прямий Web Audio API;
- Playwright;
- повне озвучення;
- історія діалогів;
- галерея відкритих кінцівок;
- зміна швидкості тексту;
- перезапуск окремої сцени;
- синхронізація прогресу між пристроями;
- сервер і база даних;
- складні відеоролики та унікальна анімація кожного вибору.

## Підсумкова формула стеку

**React + TypeScript + Vite + типізований сценарій + `useReducer` + `localStorage` + Howler.js + CSS animations + опційний Vitest + мінімальна PWA + Vercel.**
